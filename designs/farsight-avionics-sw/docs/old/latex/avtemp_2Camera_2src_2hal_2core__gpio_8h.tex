\hypertarget{index_intro_sec}{}\doxysubsection{\texorpdfstring{Introduction}{Introduction}}\label{index_intro_sec}
The Core\+GPIO hardware IP includes up to 32 general-\/purpose input/\+output GPIOs. This driver provides a set of functions for controlling the GPIOs as part of a bare-\/metal system where no operating system is available. These drivers can be adapted for use as part of an operating system, but the implementation of the adaptation layer between this driver and the operating system\textquotesingle{}s driver model is outside the scope of this driver.\hypertarget{avtemp_2Camera_2src_2hal_2core__gpio_8h_driver_configuration}{}\doxysubsection{\texorpdfstring{Driver Configuration}{Driver Configuration}}\label{avtemp_2Camera_2src_2hal_2core__gpio_8h_driver_configuration}
The individual IOs of Core\+GPIO can be configured either in the hardware flow or as part of the software application through calls to the \doxylink{core__gpio_8c_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function. GPIOs configured as part of the hardware are fixed and cannot be modified using a call to the GPI\+\_\+config() function.\hypertarget{avtemp_2Camera_2src_2hal_2core__gpio_8h_theory_op}{}\doxysubsection{\texorpdfstring{Theory of Operation}{Theory of Operation}}\label{avtemp_2Camera_2src_2hal_2core__gpio_8h_theory_op}
The Core\+GPIO driver uses the Actel Hardware Abstraction Layer (HAL) to access hardware registers. You must ensure that the Actel HAL is included as part of your software project. The Actel HAL is available through the Actel Firmware Catalog.

The Core\+GPIO driver functions are logically grouped into the following groups:\+
\begin{DoxyItemize}
\item Initialization
\item Configuration
\item Reading and writing GPIO state
\item Interrupt control
\end{DoxyItemize}

The Core\+GPIO driver is initialized through a call to the \doxylink{core__gpio_8c_a09658eeda1c1d7d30f8fc5728daeff31}{GPIO\+\_\+init()} function. The \doxylink{core__gpio_8c_a09658eeda1c1d7d30f8fc5728daeff31}{GPIO\+\_\+init()} function must be called before any other GPIO driver functions can be called.

Each GPIO port is individually configured through a call to the \doxylink{core__gpio_8c_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function. Configuration includes deciding if a GPIO port is going to be used as input, output, or both. GPIO ports configured as inputs are further configured to generate interrupts based on the state of input. Interrupts is either level-\/ or edge-\/sensitive. ~\newline
 Note that a Core\+GPIO hardware instance is generated as part of the hardware flow with a fixed configuration for some or all of its IOs. Attempting to modify the configuration of such a hardware-\/configured IO using the \doxylink{core__gpio_8c_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function has no effect.

\hypertarget{index_intro_sec}{}\doxysubsection{\texorpdfstring{Introduction}{Introduction}}\label{index_intro_sec}
The Core\+GPIO hardware IP includes up to 32 general-\/purpose input/\+output GPIOs. This driver provides a set of functions for controlling the GPIOs as part of a bare-\/metal system where no operating system is available. These drivers can be adapted for use as part of an operating system, but the implementation of the adaptation layer between this driver and the operating system\textquotesingle{}s driver model is outside the scope of this driver.\hypertarget{avtemp_2Camera_2src_2hal_2core__gpio_8h_driver_configuration}{}\doxysubsection{\texorpdfstring{Driver Configuration}{Driver Configuration}}\label{avtemp_2Camera_2src_2hal_2core__gpio_8h_driver_configuration}
The individual IOs of Core\+GPIO can be configured either in the hardware flow or as part of the software application through calls to the \doxylink{avtemp_2Camera_2src_2hal_2core__gpio_8h_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function. GPIOs configured as part of the hardware are fixed and cannot be modified using a call to the GPI\+\_\+config() function.\hypertarget{avtemp_2Camera_2src_2hal_2core__gpio_8h_theory_op}{}\doxysubsection{\texorpdfstring{Theory of Operation}{Theory of Operation}}\label{avtemp_2Camera_2src_2hal_2core__gpio_8h_theory_op}
The Core\+GPIO driver uses the Actel Hardware Abstraction Layer (HAL) to access hardware registers. You must ensure that the Actel HAL is included as part of your software project. The Actel HAL is available through the Actel Firmware Catalog.

The Core\+GPIO driver functions are logically grouped into the following groups:\+
\begin{DoxyItemize}
\item Initialization
\item Configuration
\item Reading and writing GPIO state
\item Interrupt control
\end{DoxyItemize}

The Core\+GPIO driver is initialized through a call to the \doxylink{avtemp_2Camera_2src_2hal_2core__gpio_8h_a09658eeda1c1d7d30f8fc5728daeff31}{GPIO\+\_\+init()} function. The \doxylink{avtemp_2Camera_2src_2hal_2core__gpio_8h_a09658eeda1c1d7d30f8fc5728daeff31}{GPIO\+\_\+init()} function must be called before any other GPIO driver functions can be called.

Each GPIO port is individually configured through a call to the \doxylink{avtemp_2Camera_2src_2hal_2core__gpio_8h_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function. Configuration includes deciding if a GPIO port is going to be used as input, output, or both. GPIO ports configured as inputs are further configured to generate interrupts based on the state of input. Interrupts is either level-\/ or edge-\/sensitive. ~\newline
 Note that a Core\+GPIO hardware instance is generated as part of the hardware flow with a fixed configuration for some or all of its IOs. Attempting to modify the configuration of such a hardware-\/configured IO using the \doxylink{avtemp_2Camera_2src_2hal_2core__gpio_8h_a59c399acb6c889d5727d6109fbec85c6}{GPIO\+\_\+config()} function has no effect.
